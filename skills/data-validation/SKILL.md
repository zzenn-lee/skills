# Data Validation

A는 분석 전에 데이터를, B는 제출 전에 결과를 점검한다. 모든 항목을 기계적으로 돌리지 말고, 결론을 바꿀 수 있는 것부터 본다. 결과는 `docs/02_data_profile.md`(A)와 `docs/04_validation.md`(B)에 남긴다.

## A. 데이터 품질

먼저 데이터의 용도, grain(한 행이 무엇인지), 키를 정한다. 문제처럼 보이는 것의 상당수는 grain이 섞였거나 조인이 중복된 것이다.

| 항목 | 볼 것 |
|---|---|
| 완전성 | 열별 결측률을 기간·그룹별로. 빈 문자열, `unknown`, `N/A`, `0`, `-1` 같은 대체값 |
| 고유성 | 완전 중복 행, 키 중복, 공백·대소문자를 정리한 뒤의 중복 |
| 유효성 | 타입 변환 실패, 형식(ID·날짜·코드), 범위(음수 수량, 100% 초과 비율, 미래 날짜), 허용값 |
| 일관성 | 열 사이 규칙(취소 아님인데 취소일 있음, 종료가 시작보다 앞섬), 단위 혼합 |
| 무결성 | 짝이 없는 외래키, 조인 전후 행 수와 고유 키 수, 다대다 조인 폭증 |
| 시간 | 최신 날짜, 빠진 기간, 늦게 들어온 최근 데이터, 소급 수정 |
| 분포 | 기간별 행 수·결측률·범주 비율 변화, 새로 생기거나 사라진 범주. 이상값은 분위수·IQR·MAD로 먼저 본다 |

- 건수보다 비율을 보고, 시간과 주요 그룹으로 나눠 본다.
- 발견마다 적는다: **무엇 / 근거(건수·비율·구간) / 결과에 주는 영향 / 심각도 / 추정 원인 / 처리**.
- 심각도: **치명**(키 중복, grain 혼재처럼 결론을 뒤집음), **높음**(결과를 크게 치우치게 함), **중간**(국소적, 기록 필요), **낮음**(영향 없음).
- 처리 규칙을 먼저 적고 적용한다. 행을 조용히 지우지 말고 제외 건수를 이유별로 남긴다. 데이터로 판단할 수 없는 처리 방법은 담당자 질문(`Q#`)으로 만든다.

## B. 결과 검증

1. **주장 목록**: 보고할 핵심 수치, 결론, 비교 기준을 뽑는다. `docs/00_problem.md`의 모든 R#가 어딘가에 대응되는지 본다.
2. **질문과 방법**: 문제가 물은 질문에 답하는가 (더 쉬운 다른 질문이 아니라). 대상·필터·기간·분모·단위가 문제의 정의와 맞는가. 인과 표현("~때문에", "~효과")에 실험이나 그에 준하는 근거가 있는가.
3. **재계산**: 핵심 수치를 본 코드와 별개의 코드로 원시 분자·분모부터 다시 계산한다. 레코드 몇 개를 조인·필터·출력까지 따라가 본다. 의외의 결과는 다른 계산 경로로 한 번 더 확인한다.
4. **함정**:
   - 조인 폭증: 조인 전후 행 수와 고유 키 수를 비교한다. 오른쪽 표를 먼저 필요한 grain으로 집계한다.
   - 평균의 평균: 그룹 크기가 다르면 분자·분모 합계로 다시 계산한다.
   - 부분 기간 비교, 기간 사이 분모 정의 변화, 시간대 차이.
   - 생존 편향(사라진 대상이 빠짐), 결과로 정의한 그룹 비교.
   - 심슨의 역설(전체와 그룹별 방향이 다름), 다중 비교, 작은 표본, 이상값이 끌어올린 평균.
5. **그럴듯함**: 크기가 상식적인가. 비율 합이 100% 근처인가. 0%·100%, 급변·평탄, 딱 떨어지는 숫자, 가설을 너무 완벽하게 지지하는 결과에는 이유를 찾는다.
6. **모델·예측**: 누수와 기준선 비교는 `guide.md` ⑤를 따른다.
7. **표현**: 막대그래프 축은 0부터. 단위·기간·범위를 표시한다. 제목과 문장이 데이터보다 많이 주장하지 않는다. 정밀도는 필요한 만큼만.
8. **판정**:
   - **제출 가능**: 핵심 수치가 재계산으로 확인됐고 남은 문제는 사소하다.
   - **단서 필요**: 방향은 맞지만 함께 밝혀야 할 가정·한계·미확인 항목이 있다.
   - **수정 필요**: 수치·분모·조인·기간·대상 중 하나라도 결론을 바꿀 만큼 틀렸거나 확인되지 않았다.

   막는 문제(수정해야 제출 가능)와 단서(밝히면 되는 것)를 나눠 적는다. 확인하지 못한 항목은 무엇이 있어야 확인되는지와 함께 적는다.
